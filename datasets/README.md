# datasets/ — what goes here and where it comes from

No data is committed. This folder ships only the small **configuration** files the scripts rely on (label maps,
split reports, statistics); every `.jsonl`, `.parquet` and `gold_*.json` file is gitignored. Download links for the
released sets will be added here; until then the recipes in `recipes/data_*.sh` rebuild everything from sources.

## The record format

One JSON object per line. Every declared label appears in every record (an empty list is explicit negative
supervision); surfaces are verbatim substrings that GLiNER2's whole-word matcher can find; relations name the
**tail** argument in Turkish ("kimlik numarası sahibi" = the person the id belongs to):

```json
{"id": "e08-4471",
 "input": "KAN TAHLİLİ RAPORU\n\nHasta: Yaşar Ergin\nT.C. Kimlik No: 49738174980 ...",
 "output": {"entities": {"ad soyad": ["Yaşar Ergin", "Dr. Berkan Ertürk"], "kimlik numarası": ["49738174980"], "araç plakası": []},
            "relations": [{"kimlik numarası sahibi": {"head": "49738174980", "tail": "Yaşar Ergin"}},
                          {"lakap sahibi": {"head": "", "tail": ""}}]}}
```

The full rules, and why each exists, are in `docs/DATA.md`.

## Real-document sets

`gt/*/gt.jsonl` hold real personal data (pseudonymised) and stay private. Their schema, so you can build your own:
`{docname, text, spans:[{start,end,label,text,entity_id}], entities:[{id,label,mentions:[{start,end}],same_as,role}],
relations:[{head,relation,tail}]}` with taxonomy node ids as labels (`configs/labels/taxonomy_labels_tr.json` maps them to
the Turkish query names). `scripts/bench_gt.py` and the cross-model harness (`scripts/run_benchmark.py`) consume this shape.
